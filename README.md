# 🏭 INDUSTRA AI — Predictive Maintenance with Ontology-Assisted Root Cause Analysis

> A neuro-symbolic predictive maintenance system that combines machine learning with semantic ontology reasoning to detect machine failures, explain why they occur, and recommend corrective actions.

---

## 🎯 Project Overview

Standard ML-based predictive maintenance systems tell you **what** will fail. This system tells you **what**, **why**, and **what to do about it** — by combining a Random Forest classifier with an OWL/RDF knowledge graph reasoner.

### The Core Innovation

The diagnostic rules and their thresholds are stored in the ontology (`factory_ontology.ttl`), not in code. For every request the reasoner evaluates them against the sensor readings:

- If a rule fires, it is a sufficient condition and decides the failure mode (HDF, PWF, OSF).
- If no rule fires, the ontology rejects ML predictions for modes whose rules are declared complete, and for random failures (declared unpredictable); the best remaining ML class wins (No Failure or TWF).

This is a **neuro-symbolic architecture** — statistical learning for the part of the problem that is not rule-expressible (tool wear), symbolic reasoning for the rest, and ontology-backed root causes for every diagnosis.

## 🚀 Setup & Run

### 1. Clone the repo
```bash
git clone https://github.com/Gauransh13738/minor_project_macfail_1.0.git
cd minor_project_macfail_1.0
```

### 2. Create virtual environment
```bash
python3 -m venv venv
source venv/bin/activate        # Mac/Linux
venv\Scripts\activate           # Windows
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

### 4. Generate model.pkl
> model.pkl is not included in the repo (too large for git). Generate it by running eda.ipynb.

```bash
pip install jupyter
jupyter notebook eda.ipynb
# Run All Cells — model.pkl will be saved to the project root
```

### 5. Start the backend
```bash
uvicorn app:app --reload
# Running on http://127.0.0.1:8000
# API docs at http://127.0.0.1:8000/docs
```

### 6. Start the frontend
```bash
cd frontend
npm install
npm run dev
# Running on http://localhost:5173
```

## 🔌 API Endpoints

### `POST /predict` — ML + Ontology (full pipeline)
```json
{
  "Type": "M",
  "Air_temperature_K": 300.0,
  "Process_temperature_K": 307.5,
  "Rotational_speed_rpm": 1300,
  "Torque_Nm": 40.0,
  "Tool_wear_min": 10
}
```

**Response** (illustrative; the ML numbers depend on your trained `model.pkl`):
```json
{
  "failure_class": 2,
  "failure_type": "Heat Dissipation Failure",
  "confidence": 1.0,
  "ontology_assisted": true,
  "decision_source": "ontology_rule",
  "ml_prediction": "No Failure",
  "ml_confidence": 0.98,
  "rules_fired": [
    {"id": "Rule_HDF", "description": "Process-air temperature gap below 8.6 K while rotating below 1380 rpm"}
  ],
  "vetoed": [],
  "root_cause_analysis": [
    {
      "root_cause": "Temperature delta between air and process is too low (< 8.6K)",
      "sensors_involved": ["Air temperature in Kelvin", "Process temperature in Kelvin"],
      "recommended_action": "Check coolant flow. Clean heat exchangers. Verify cooling system is operational."
    }
  ],
  "method": "Ontology rule"
}
```

`confidence` is the measured precision of the fired rule on AI4I when a rule decides, otherwise the ML probability of the chosen class.
`decision_source` is `ontology_rule`, `ontology_veto` (ML's pick was ruled out) or `ml`.

## 📊 Model Performance

Every number below is regenerated by `python evaluate.py` (see `requirements-research.txt`);
full tables, per-split CSVs and a confusion-matrix figure are written to `results/`.
Training strategy: SMOTE oversampling + balanced class weights, Random Forest.

Mean ± sd over 10 random stratified 80/20 splits of AI4I 2020:

| System | Accuracy | Macro-F1 | HDF F1 | PWF F1 | OSF F1 | False-alarm rate |
|---|---|---|---|---|---|---|
| ML only | 90.76 ± 1.38% | 0.514 ± 0.035 | 0.632 | 0.715 | 0.669 | 8.5% |
| Old hybrid (confidence-gated override) | 90.92 ± 1.32% | 0.527 ± 0.034 | 0.698 | 0.723 | 0.669 | 8.5% |
| Rules only (ontology, no ML) | 99.35 ± 0.00% | 0.663 ± 0.003 | 1.000 | 0.992 | 0.988 | 0.0% |
| **ML + Ontology (current)** | 97.12 ± 0.38% | **0.680 ± 0.008** | 1.000 | 0.992 | 0.988 | 2.5% |

Notes: TWF (F1 ≈ 0.12) and RNF (F1 = 0) remain essentially unpredictable. AI4I is a synthetic
dataset whose failure labels follow threshold rules, so results here show the benefit of encoding
domain rules in a knowledge layer; they are not evidence about real-plant performance.

## 🧠 Ontology Structure

Aligned with the W3C **SOSA/SSN** vocabulary (`mf:Machine` ⊑ `sosa:Platform`, `mf:Sensor` ⊑ `sosa:Sensor`,
`mf:has_sensor` ⊑ `sosa:hosts`) and extended with executable diagnostic rules:
```
Machine → has_sensor → Sensor
FailureMode → caused_by → RootCause
RootCause → measured_by → Sensor
RootCause → has_action → "Recommended maintenance action"
```
**Failure modes modelled:**
- Tool Wear Failure (TWF)
- Heat Dissipation Failure (HDF)
- Power Failure (PWF)
- Overstrain Failure (OSF)
- Random Failure (RNF)

## ✨ Features

- **ML vs Ontology comparison panel** — side-by-side with confidence delta callout
- **Ontology-constrained hybrid engine** — rules stored in the ontology decide HDF/PWF/OSF; the ontology vetoes ML predictions it rules out; the response shows which rule fired
- **Root cause analysis** — sensors implicated + recommended action per cause
- **Severity badges** — CRITICAL / WARNING / SAFE per prediction
- **Live sensor dashboard** — 5 arc gauges with safe/warning/danger zones, auto-predicts on slider change
- **Prediction history timeline** — color-coded cards with severity and ontology-assist indicators
- **PDF maintenance report** — one-click export with full diagnosis
